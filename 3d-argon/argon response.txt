### 3. Critical Conflicts and Risks (Ranked by Severity)

1. **`CRITICAL` — `UnreliableRemoteEvent` vs. Frozen Remote Contract (`default.project.json`, `Remotes.spec.luau`, `MASTER_IMPLEMENTATION_PLAN.md` §10.3)**:
* Using an `UnreliableRemoteEvent` for Board Pulse cycle broadcasts or adding any new remote breaks `src/server/Tests/Unit/Remotes.spec.luau` (lines 6, 29–55), which enforces the exact 10 remotes in `ReplicatedStorage.Remotes` and verifies `BoardPulseEvent.ClassName == "RemoteEvent"`. Furthermore, dropped unreliable packets would leave clients without hazard warnings on a competitive board.


2. **`CRITICAL` — Path A (`D-024` / `D-025` / `D-026`) Deterministic Simulation & Rollback Violation**:
* Gate 0 selected **Path A (Roblox Server Authority)** (`DECISION_LOG.md` `D-024`). Under `D-025` item 3 and `MASTER_IMPLEMENTATION_PLAN.md` §9.3:
* All physics-affecting hazard math (Ice steering/damping multipliers, Magnetic Storm radial pull, Boost Runway `+18 studs/s` kick) **must** execute inside the shared `RunService:BindToSimulation()` callback using synchronized simulation `time()`, never `os.clock()`/`tick()` or a server-only `Heartbeat` loop that bypasses client prediction.
* One-shot simulation events (such as the Boost Runway per-sphere trigger stamp for `(RoundId, CycleId)`) must be stored as synchronized state/attributes with monotonically increasing sequence IDs so client resimulation does not re-trigger the `+18 studs/s` impulse or duplicate VFX (`D-025` item 3).
* Per `D-026` item 3 (`FAIL-008`), client visualizers/FX controllers **must poll** attributes on predicted instances in `PreRender`/`RenderStepped` rather than connecting `GetAttributeChangedSignal`, which does not fire on predicted instances during rollback in Studio `0.743`.




3. **`HIGH` — Undocumented Hazard Knockback Multipliers (`MASTER_IMPLEMENTATION_PLAN.md` §7.1 & §8.5)**:
* Adding a knockback multiplier for spheres colliding on Ice, Magnetic Storm, or Boost Runway violates `MASTER_IMPLEMENTATION_PLAN.md` §7.1 (*"avoid undocumented per-hazard damage multipliers"*) and §8.5 (`rawDeltaV` uses only `attackerOutgoingFactor` from Kinetic Dash and `victimResistanceFactor` from Cryo Brake).


4. **`HIGH` — Mutating `CollisionTile` Physical Friction vs. Mathematical Slip (`MASTER_IMPLEMENTATION_PLAN.md` §6.2, §6.3, §7.4)**:
* Mutating `CustomPhysicalProperties` on `CollisionTile` instances during Ice Corridor instead of applying `GameConfig.Hazards.Ice.SteeringMultiplier = 0.45` and `LateralDampingMultiplier = 0.25` in `SimulationMath.luau` conflicts with §6.2/§6.3, desynchronizes Path A rollback prediction, and violates the rule that `CollisionTile` properties remain static after grid creation.


5. **`MEDIUM` — `BoardPulsePayload` Field Name Mismatch Between `TASK-05` Card Prose and Frozen `src/shared/Types.luau**`:
* `tasks/TASK-05-BOARD-PULSE.md` Req 2 mentions `Pattern, Phase, EventId, WarningAt, ActivationAt, EndAt, ResetEndAt`, whereas the frozen `src/shared/Types.luau` (`BoardPulsePayload`, lines 92–102) uses `RoundId, CycleId, Phase, Meta, StartAt, WarningAt, ActiveAt, ResetAt, EndAt`. Because `--!strict` and `luau-lsp` enforce `Types.luau` (`MASTER_IMPLEMENTATION_PLAN.md` §0.2 item 3), writing `ActivationAt`, `ResetEndAt`, or top-level `Pattern` will fail static type analysis.


6. **`MEDIUM` — Pending Arena-Tile 3D Asset Architecture vs. `TASK-02` / `MASTER_IMPLEMENTATION_PLAN.md` §6.2**:
* `MASTER_IMPLEMENTATION_PLAN.md` §6.2 (lines 366–368) and `GameConfig.Arena` (`GameConfig.luau` lines 47–49) define three logical tile layers per cell:
1. `CollisionTile`: `(12, 2, 12)` invisible, anchored, `CanCollide = true`, collision group `ArenaTile`.
2. `VisualTile`: `(11.8, 2, 11.8)` non-colliding (`CanCollide = false`, `CanTouch = false`), alternating `TileDark (32, 38, 54)` and `TileLight (42, 50, 70)` by checkerboard parity `(x + z) % 2`.
3. `HazardOverlay`: non-colliding (`CanCollide = false`, `CanTouch = false`), size around `(11.4, 0.05, 11.4)` in greybox (`TASK-02`), or modular overlay meshes (`SM_ArenaTile_Overlay_01..06`) in `TASK-09`.


* Furthermore, `tasks/TASK-02-GRID-AND-COLLAPSE.md` line 34 explicitly instructs: ***"Do not add final decorative meshes until grid/collision tests pass."*** And if the multi-node 3D tile meshes are used later in `TASK-09`, `PulseClientVisualizer` must preserve the checkerboard parity (`TileDark` vs `TileLight` on the recessed deck) and must **never** swap or tween the `12 × 2 × 12` `CollisionTile`.

2. **Pure Deterministic Pattern Selection (`src/shared/Modules/PatternDefinitions.luau`)**:
